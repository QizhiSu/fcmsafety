# 0909 实测三处 P1 修复：行序对齐 / 批量入口 / toxtree 可选化

2026-09-09 对"检测机构检出 100 种物质 → 筛查"的端到端实测（`0909测试结果_v1.md`）暴露三处 P1 问题。本文记录三项修复决策，避免回归时误判。

## 1. Toxtree 输出按输入行序对齐，不信任 CLI 身份列

空 CAS 的输入行会让 Toxtree CLI 输出整行左移一列（实测 80/100 行受影响，Cramer 分级值被挤进 CRAMERFLAGS 列）。原 `.normalize_toxtree_output()` 只校验列名存在与行数兜底，错位被静默读入，`assign_toxicity` 按 SMILES 回填时无 CAS 物质的 Cramer 分级静默丢失、无警告。

**Decision**：结果文件读回后 (a) 行数与 SMILES 过滤后输入不一致即 stop；(b) 检测身份列（NAME/CAS/SMILES）与输入逐行不一致时 warning 并 (c) 一律用输入身份列按行序重建输出身份列、错位行的结果/FLAGS/决策路径列置 NA（宁缺毋滥）。结果列定位与输出列结构不变，`assign_toxicity` 消费方式（`tox$SMILES`/`tox$Cramer.rules`）零变化。

**Consequences**：正常数据（行数一致、身份列本就一致）行为不变、无警告；空 CAS 数据获得显式警告而不再静默错配。代价：错位行的 Cramer 分级不再被"碰巧"使用（置 NA），需要用户补 CAS 重跑或人工核对。可选增强（从 flags 列挖回真实分级）留待后续。

## 2. 组物质筛查：原函数保持单物质，另开批量入口

`assign_group_membership()` 从文档到实现都是单物质标量设计（`normalize_input_identity` 的 CAS/InChIKey/SMILES/分子式识别），工作流却把整张 100 行 data.frame 传进来 → `nzchar(trimws(df))` 报 `'length = 6' in coercion to 'logical(1)'`，无任何指引。

**Decision**：不做"改造原函数吃整表"的大重构（会推翻单物质语义、波及既有 screen 链测试），而是：(a) `normalize_input_identity()` 与 `assign_group_membership()` 入口显式拒绝非标量/整表输入并指向批量版；(b) 新增导出 `assign_group_membership_table(data)`：逐行按 InChIKey > CAS > SMILES > Formula > NAME(online) 优先级取标识归一，registry 一次查询全表复用，单行失败不中断（记入 `attr(out, "errors")`），输出带 `input_index`/`input` 便于 merge 回原表；(c) 抽出 `.screen_identity()` 供两个入口共用。

**Consequences**：单物质调用方零破坏；批量场景有了第一公民入口（对应 GROUP_MEMBERSHIP_NEXT_STEPS 的"方向 5"）。代价：多一个需长期维护的公开函数；NAME-only 行离线必失败（属性限制，记 errors 而非中断）。

## 3. assign_toxicity 的 toxtree 从硬前置降为可选

原逻辑：toxtree 结果文件不存在时，无 SMILES 列的数据直接 `stop`——纯法规清单匹配被 Cramer 分级这个可选增强卡死；且该检查在 InChIKey 校验之前，无 InChIKey 数据先撞到 toxtree 错误，误导排查方向。

**Decision**：保留默认参数 `toxtree_result = "toxtree_results.csv"`（向后兼容），改为跳过式——文件不存在且有 SMILES → 自动补跑（原行为不变）；文件不存在且无 SMILES → message 一次并跳过 Cramer，法规匹配继续（`Cramer_rules` 列仍产出、全 "-"，列结构稳定）。InChIKey 校验移到 toxtree 处理之前。另为测试/自定义部署给 `assign_toxicity` 增加 `db_path = NULL` 透传。

**Consequences**：只在"文件缺失 + 无 SMILES"这一条路径上改变行为（由报错变为跳过），其余路径不变；`Cramer_rules` 列恒存在，下游脚本/relocate 逻辑不受影响。代价：用户可能没注意到 Cramer 被跳过——以 message 提示补偿（也可考虑后续加显式返回标记）。

## 验证约束

本机 `R CMD check`/`INSTALL` 的 lazy-load 阶段有环境 bug（rlang 系）必崩，三个修复全部用 `pkgload::load_all` + `testthat::test_dir` 验证（不依赖进程退出码，退出 segfault 不影响落盘）。
