🤖 AI 辅助开发指南

FCMSafety fcmsafety-v2 分支 · 实习生用 AI 辅助开发的操作手册

第一步：准备工作（只需做一次）

📋 给 AI 的第一个 Prompt（复制粘贴即可）： 
我想开发一个 R 包项目。请帮我做以下事情：

1. 在终端克隆这个 GitHub 仓库：
   git clone https://github.com/QizhiSu/fcmsafety.git
   cd fcmsafety

2. 切换到 fcmsafety-v2 分支：
   git checkout fcmsafety-v2

3. 确认当前在正确分支：
   git branch -v

完成后告诉我当前分支是什么，以及项目里有哪些主要文件。
⚠️ 重要提醒：这个项目有两个分支：
  • main — 旧版本，不要动
  • fcmsafety-v2 — 新版本，所有开发都在这个分支上
每次开始新任务前，确认 AI 在 fcmsafety-v2 分支上工作。
💡 AI 开发的工作模式：你会把需求告诉 AI，AI 帮你写代码、解释代码、查错。你只需要复制粘贴 Prompt，AI 会帮你执行命令和修改代码。

第二步：日常开发流程

2.1 开始一个新任务

📋 开始开发新功能（复制粘贴，把需求改成你的）： 
我需要在 fcmsafety-v2 分支上开发一个新功能。

请先确认当前在 fcmsafety-v2 分支，然后帮我：

1. 创建一个新的功能分支：
   git checkout -b feature/功能名称

2. 阅读项目中的 INTERN_HANDOFF.md 文档，了解项目结构

3. 告诉我：
   - 当前在哪个分支
   - 项目的主要 R 文件有哪些
   - INTERN_HANDOFF.md 里有什么重要内容

（把"功能名称"改成你实际要做的，比如 "add-china-sml-updater"，
 把"需求"改成你具体想实现的功能）

2.2 让 AI 写代码

📋 让 AI 实现具体功能： 
请帮我实现以下功能：

[在这里描述你要实现的功能]

注意事项：
- 所有代码写在 fcmsafety-v2 分支的功能分支上
- 不要修改 main 分支
- 修改代码后，用 git status 确认改动
- 写完代码后，运行 devtools::check() 检查是否有错误
📋 让 AI 修复 bug： 
我在运行代码时遇到了这个错误：
[把错误信息复制到这里]

请帮我：
1. 分析这个错误的原因
2. 找到出错的代码位置
3. 修复这个问题
4. 解释修复的原理

2.3 让 AI 解释代码

📋 让 AI 解释某个文件或函数： 
请帮我解释这个文件/函数：

[把文件名或函数名写在这里，比如 "R/assign_toxicity.R"
 或者 "assign_toxicity 函数"]

请告诉我：
- 这个文件/函数的作用是什么
- 核心逻辑是什么
- 输入和输出是什么

第三步：提交代码并推送

3.1 让 AI 帮你提交代码

📋 提交当前改动： 
请帮我提交当前的代码改动：

1. 先查看改动内容：
   git status
   git diff

2. 告诉我有哪些文件被修改了

3. 添加改动并提交（请根据改动内容写一个合适的提交信息）：
   git add .
   git commit -m "你的提交信息"

4. 把提交推送到远程：
   git push -u origin feature/功能名称

3.2 让 AI 帮你写提交信息

📋 让 AI 决定提交信息： 
请查看当前的代码改动（git diff），然后：

1. 告诉我这些改动做了什么
2. 根据改动内容写一个合适的提交信息（英文，中文都可以）
3. 执行 git add . 和 git commit 提交
4. 如果是第一次推送，执行 git push -u origin 当前分支名
⚠️ 提交前一定要看：让 AI 执行 git diff 之前，先让 AI 显示改动内容，确认改动正确再提交。不要盲目提交。

第四步：创建 Pull Request（让维护者审核）

📋 让 AI 帮你创建 PR： 
请帮我创建 Pull Request：

1. 确认当前在哪个分支：git branch -v

2. 确认有哪些改动：git status && git diff --stat

3. 确认远程分支已推送：git log origin/feature/功能名称..HEAD

4. 告诉我我应该去 GitHub 做什么操作：
   - 打开哪个网址
   - 选择哪些选项
   - 填写什么内容
✅ 流程总结：
开发 → 提交到功能分支 → 推送到你的 GitHub Fork → 在 GitHub 上创建 Pull Request → 等待维护者审核合并

第五步：同步最新的代码（定期做）

📋 让 AI 帮你同步上游更新： 
请帮我同步 fcmsafety-v2 分支的最新代码：

1. 添加上游仓库（如果还没有）：
   git remote add upstream https://github.com/QizhiSu/fcmsafety.git

2. 获取上游最新代码：
   git fetch upstream

3. 切换到 fcmsafety-v2：
   git checkout fcmsafety-v2

4. 合并上游更新：
   git merge upstream/fcmsafety-v2

5. 如果有冲突，告诉我哪些文件冲突，需要我怎么处理

6. 推送更新到我的 Fork：
   git push origin fcmsafety-v2

第六步：常用场景模板

场景给 AI 的 Prompt
不知道从哪开始 请阅读 INTERN_HANDOFF.md，然后告诉我这个项目的核心功能是什么，实习生主要做哪些工作
想看数据库状态 请运行 fcmsafety_status() 和 check_database_status()，告诉我数据库里有哪些表，各有多少条记录
想测试某个函数 请用 tests/testthat/fixtures/example_input.csv 的数据测试 assign_toxicity 函数
想让 AI 审阅代码 请审阅 R/assign_toxicity.R 这个文件，告诉我有哪些潜在问题，如何改进
想添加测试 请为 R/assign_toxicity.R 中的函数添加测试用例，放在 tests/testthat/ 目录下
运行 R CMD check 请运行 devtools::check() 并告诉我检查结果，有没有错误或警告
重新生成文档 请运行 devtools::document() 重新生成 R 包的文档
查看改动历史 请运行 git log --oneline -10 告诉我最近的提交历史

第七步：AI 开发安全规则

⚠️ AI 开发禁止做的事情（让 AI 帮你做之前先想一下）：
  • ❌ 不要删除 main 分支
  • ❌ 不要修改 main 分支的内容
  • ❌ 不要强制推送 git push --force
  • ❌ 不要删除重要的数据库文件或配置文件
  • ❌ 不要提交包含密码、密钥等敏感信息的代码
  • ❌ 不要直接推送到 QizhiSu/fcmsafety 仓库（没有权限）
💡 正确的做法：
  • ✅ 所有开发在 feature/你的功能名 分支上进行
  • ✅ 推送到自己的 GitHub Fork（你的用户名/fcmsafety）
  • ✅ 通过 Pull Request 让维护者审核
  • ✅ 提交前让 AI 显示 git diff 确认改动内容
  • ✅ 如果 AI 要执行删除文件等危险操作，先问清楚再确认

第九步：遇到问题怎么办

  1. AI 写错了代码？ 让 AI 解释代码逻辑，指出哪里不对，让 AI 重写
  2. 不知道怎么做？ 把你的问题完整描述给 AI，包括你看到的错误信息
  3. Git 报错？ 把错误信息复制给 AI，让 AI 帮你分析和解决
  4. 不确定能不能做？ 先问 AI "这样做可以吗？" 确认安全后再执行
  5. AI 不知道怎么解决问题？ 在 GitHub 上提交 Issue，描述清楚问题
  6. 需要帮助？ 联系项目维护者苏麒（93212874sqz@gmail.com）
